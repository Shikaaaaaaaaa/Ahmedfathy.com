# Ahmed Fathy Portfolio — Build Plan

## Positioning

Ahmed is an AI Product Engineer who turns operational gaps into production software, agentic workflows, and data-backed decisions. The portfolio must prove end-to-end ownership rather than present a flat list of technologies.

## Concept

**Systems Lab:** visitors inspect real workflows as they move from input through architecture, automation, verification, and outcome.

The signature interaction is an execution trace based on the real WeIN offer workflow:

`Provider intake → offer intelligence → agentic generation → groundedness gate → delivery`

## Audience

- Startup founders looking for product-minded technical ownership
- AI and product engineering hiring managers
- Teams building internal tools, operational software, or applied AI systems

## Site Structure

1. Positioning and live execution trace
2. Discover / Architect / Ship operating model
3. Featured systems with category filters
4. Complete project archive
5. Current SaaS build status and build log
6. About, capabilities, résumé, and contact
7. Individual flagship case studies

## Delivery Milestones

### Milestone 1 — Foundation — complete

- Replace the old template while preserving the original page and notebooks
- Establish palette, typography, grid, responsive shell, navigation, and contact path
- Add structured project data and archive

### Milestone 2 — Signature system — complete

- Build the interactive WeIN execution trace
- Add manual and automated workflow states
- Support reduced motion and mobile layout

### Milestone 3 — Project discovery — complete

- Add product, AI/automation, and data/ML filters
- Separate flagship work from the complete archive
- Verify controls on desktop and mobile

### Milestone 4 — Case studies — next

- Create reusable case-study layout
- Document problem, actors, workflow, role, architecture, decisions, safeguards, result, and evidence
- Add system diagrams and real product screenshots where public sharing is allowed

### Milestone 5 — Current SaaS build log

- Confirm public product name and one-sentence description
- Document current phase and completed milestones
- Add an honest “in development” timeline
- Separate public architecture from private implementation details

### Milestone 6 — Final polish

- Add résumé download and social preview image
- Audit accessibility, keyboard flow, metadata, and external links
- Compress assets and test performance
- Final visual QA at desktop, tablet, and mobile sizes

### Milestone 7 — Release

- Review all public claims and confidential material
- Commit and push after approval
- Deploy through GitHub Pages or the selected host
- Connect the final domain and analytics if desired

## Quality Rules

- Show evidence before technology labels
- Never imply an unfinished system is launched
- Use real workflow states instead of generic AI graphics
- Keep every core action usable without animation
- Keep the mobile experience conceptually equivalent to desktop

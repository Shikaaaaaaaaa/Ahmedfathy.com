# Ahmed Fathy Portfolio

Portfolio for Ahmed Fathy, an AI Product Engineer in Cairo. It presents four flagship projects as evidence of end-to-end product ownership: from an ambiguous operating problem through workflow design, implementation, verification, and release.

## Start here

- [Shared project context](docs/PROJECT_CONTEXT.md) — the authoritative brief, live structure, project facts, visual rules, and working agreements.
- [Decision and session log](docs/DECISION_LOG.md) — dated record of what changed, why it changed, and what remains open.
- [Joint portfolio roadmap](docs/PORTFOLIO_ROADMAP.md) — the agreed Claude/Codex implementation plan and review gates.
- [Claude/Codex debate summary](docs/CLAUDE_DEBATE_SUMMARY.md) — disagreements, resolutions, and final verdict.
- [Portfolio direction](PORTFOLIO_PLAN.md) — earlier creative-direction document.
- [Miora brief](MIORA_MASTER_PROMPT.md) — a detailed exploratory prompt; it is reference material, not the current implementation plan.

## Working agreement

1. Read `docs/PROJECT_CONTEXT.md` before proposing or making visual changes.
2. Preserve existing uncommitted work unless the task explicitly replaces it.
3. Treat the four flagship projects as the priority; archive work must remain secondary.
4. Every project visual must be a real UI fragment, approved artifact, or workflow-specific construction — never generic AI decoration.
5. Record consequential decisions in `docs/DECISION_LOG.md` with the date, rationale, and affected files.
6. Do not claim unverified metrics, private customer facts, or that Medical SaaS is launched.

## THE PROMPT

```
Design a high-end, narrative-driven portfolio for Ahmed Fathy, an AI Product Engineer in Cairo who owns
operational products end-to-end: from ambiguous business problem through workflow discovery, agentic AI
architecture, full-stack build, verification, and release.

This is NOT a template portfolio, NOT a grid of screenshots, and NOT an abstract "AI aesthetic" site.
Reject: floating particles, glowing orbs, neural-network graphics, generic holograms, robot imagery.
Every visual must trace back to something real about a shipped product.

=== CORE NARRATIVE PRINCIPLE (most important instruction) ===

Each flagship project is told through THE OPERATOR whose job it changed — not through the tech stack,
and not through Ahmed. Every project scene follows the same three-beat structure:

  BEFORE   The operator buried in the real manual mess (named, specific artifacts — not "busy" props)
  RUNNING  The system Ahmed built takes over the grinding work, stage by stage
  AFTER    The operator is PROMOTED, not relaxed — they now make the judgment call the machine can't

The third beat is non-negotiable and must never resolve into "now they rest." Automation moves people
UP the value chain. In Ahmed's real architecture there is a human review gate — the machine does the
grinding, the human does the deciding. That honesty is the differentiator.

The transformation must be carried by the WORK ARTIFACT on screen, not by facial expression alone.
Face = the half-second hook. Artifact = the credibility.

=== INTERACTION MODEL ===

Scroll IS the run button. The visitor triggers each pipeline themselves and watches chaos resolve under
their own control — progressive reveal, each element building on the last. They are a participant, not
a spectator. No autoplaying loops.

=== VISUAL DIRECTION ===

Reference blend:
- Stefan Vojnovic — calm layout, generous whitespace, engineering evidence visible inside the polish
- TRIONN (trionn.com) — project scenes where REAL UI FRAGMENTS are composited into a designed
  environment. Not a flat screenshot in a frame, not an illustrated icon standing in for a UI.
  Actual interface pieces: a negotiation card, a validation checkmark, an intake row.
- Unseen Studio / Hubtown — one signature hero scene carrying the whole first impression
- Rauno Freiberg — one meaningful novelty per context, never constant decoration

Dark-first with a genuine light mode (art-directed, not a variable swap). Restrained palette,
oversized confident typography, generous negative space.

CRITICAL CONSTRAINT ON CHARACTER WORK: illustrated/character content lives INSIDE project scenes only.
The shell — navigation, typography, spacing, grid — stays rigorously professional and restrained.
Character everywhere reads junior. Character as evidence inside a disciplined frame reads high-end.

=== HERO ===

One signature 3D/illustrated object representing "product systems engineering" — a modular control
console or blueprint object that reacts to cursor movement, built from fragments that faintly echo the
four project scenes below. Oversized name treatment: "Ahmed Fathy — AI Product Engineer."
Positioning line: "I build operational products, agentic workflows, and production systems —
from ambiguous problem to shipped software."

=== THE FOUR FLAGSHIP SCENES ===
Each gets a DISTINCT operator, distinct chaos, distinct resolution, distinct motion grammar.
No shared template between them.

--- 01. WeIN Agentic Offer Pipeline (n8n · LLMs · Python · RAG) ---
OPERATOR: The Offer Specialist.
BEFORE: Buried in the real manual mess — a provider menu PDF open to page 3 of 11, a competitor
  research tab, an unread WhatsApp thread, a pricing spreadsheet named v7_FINAL_v2, a past-offers
  list being checked for duplicates by hand, a maps tab for manual location verification, an
  unanswered owner email, draft copy on rewrite #4.
RUNNING: Those scattered artifacts get swept into one orchestrated rail. Five stations light in
  sequence: Intel → Concepts → Score → Create → Review. Three validation gates resolve to green:
  merchant grounded, no duplicate, location verified.
AFTER: One review-ready output card — "Cairo Weekend Dining — 20% off · GROUNDED · AWAITING
  SPECIALIST APPROVAL" — and a visible callout marking the human decision point.
  Readout flips: research+drafting → automated; time per offer → [PLACEHOLDER];
  time spent deciding → all of it.

--- 02. WeIN Operations Portal (Flask · Supabase · JavaScript · n8n) ---
OPERATOR: The Sales / Ops lead.
BEFORE: Deals tracked across scattered WhatsApp threads, a shared spreadsheet, and memory —
  no single source of truth, follow-ups falling through.
RUNNING: A living operating board assembles: Intake → Negotiation → Signed → Launched. Cards
  physically move between columns; portal chat and notifications fire; a launch checklist
  auto-generates on signature.
AFTER: The ops lead stops chasing status and starts working blockers — the board tells them where
  attention is needed. Composite REAL portal UI fragments here (deal card, stage column header,
  notification toast), not illustrated stand-ins.

--- 03. Medical SaaS / Clinic OS (Product · AI · Full-stack — IN DEVELOPMENT) ---
OPERATOR: The clinic receptionist / front desk.
BEFORE: Drowning in phone calls, paper intake forms, follow-up reminders on sticky notes,
  double-booked rooms.
RUNNING: An architectural blueprint assembles module by module — Intake, Scheduling, Patient
  Record, Cashier/Billing, Team, Reports — like an exploded diagram clicking into place.
AFTER: Front desk moves from transcription to triage.
MANDATORY: mark this explicitly and visibly as IN DEVELOPMENT. Never present it as launched.
  No customer counts, no uptime claims, no fabricated outcomes.

--- 04. Shore Thing (React 19 · Tailwind · Motion) ---
This one breaks the operator pattern deliberately — it is brand experience, not an ops system,
so it earns the most expressive treatment. A kinetic beach-sport and DJ-culture poster world:
bouncing ball physics, palm trees, scroll-driven day-to-night lighting following the real event
rhythm (arrival → beach games → golden hour → DJ set), resolving into a real "GET TICKETS" artifact.
Use the existing Shore Thing poster artwork as the anchor for this scene's art direction.

=== SUPPORTING ARCHIVE ===
Below the four flagship scenes, a deliberately CALM, non-animated archive: Retail Profitability
Investigation, California Housing, E-commerce Spending Predictor, Parkinson's Detection + Severity,
Business Automation Library, Eldorado Operations Platform, Fieldwork Estates, AI Training Plan
Generator, Mono Pedestrian Gallery. Filters: Products / AI + Automation / Data + ML.
Flat cards, small thumbnails. It must NOT compete with the flagship scenes.

=== HARD CONSTRAINTS ===
- Legibility beats spectacle. A hiring manager with 30 seconds must grasp the value immediately.
  NO long loading screens, NO gatekeeping intros, NO navigation the visitor has to decode.
  (Explicit anti-reference: portfolios that open with a 15-second decorative preloader.)
- prefers-reduced-motion must render a complete, static, fully legible version of every scene.
- Mobile is conceptually equivalent, not stripped — reflow scenes to vertical/tap-driven,
  do not delete them.
- Lazy-load per section; nothing heavy blocks first paint.
- NO fabricated metrics. Any number is either real or absent.
- Never imply an unfinished product is launched.
- Include: résumé download, contact (email, GitHub, LinkedIn), theme toggle, and a capabilities/stack
  section kept separate from the project scenes.

=== OUTPUT ===
Deliver as a distinct exploratory build named "portfolio-3d-v1" — NOT a replacement for any existing
site. Output must be inspectable and exportable as real code (React Three Fiber / Three.js / GSAP or
equivalent) or as high-fidelity per-scene design frames, so individual scenes can be evaluated and
selectively merged into an existing hand-built portfolio rather than adopted wholesale.
```

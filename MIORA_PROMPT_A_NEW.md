# PROMPT A — Build it fresh (the new idea)

Paste everything inside the code block into Miora. This one gives it room to imagine.

```
Design and build a high-end, cinematic portfolio site for Ahmed Fathy — an AI Product Engineer based in
Cairo who owns operational products end-to-end: from an ambiguous business problem through workflow
discovery, agentic AI architecture, full-stack implementation, verification, and release.

This must feel like a premium studio-grade experience, not a portfolio template. The bar is Awwwards
Site of the Day, not "clean personal site."

=== HARD BANS (these have already been rejected twice) ===
No floating particles. No glowing orbs. No neural-network graphics. No abstract holograms. No robot
imagery. No generic "AI aesthetic." Every single visual element must trace back to something real
about a product that was actually shipped. If it could appear on any AI startup's landing page,
it does not belong here.

=== THE ORGANISING IDEA ===
Each flagship project is told through THE OPERATOR whose job it changed — not through the tech stack.
Three beats per project:

  BEFORE   The operator buried in the real manual mess (named, specific artifacts — not vague "busy" props)
  RUNNING  The system Ahmed built absorbs the grinding work, stage by stage
  AFTER    The operator is PROMOTED, not relaxed — they now make the judgement the machine cannot

The third beat is non-negotiable. It must never resolve into "now they rest." Automation moves people
UP the value chain. Ahmed's real architecture contains a human review gate: the machine does the
grinding, the human does the deciding. That honesty is the differentiator — most automation portfolios
accidentally imply "I replaced people," which reads badly to hiring managers.

The transformation is carried by the WORK ARTIFACT on screen, not by facial expression.
Face = the half-second hook. Artifact = the credibility.

=== CRAFT REQUIREMENTS (this is where portfolios usually fail) ===
- Display typography: 100px+ at desktop, tight tracking (-5% to -6%), mixed weights (200 against 800).
- Real depth: CSS/WebGL perspective, elements at different Z, parallax tied to cursor.
- Material: glass surfaces with heavy backdrop blur, layered inset highlights, dual-layer shadows,
  specular gradient overlays. Surfaces must look lit, not filled.
- Atmospheric lighting that NARRATES: colour temperature shifts with the story
  (warm amber for manual chaos → cool blue for the system running → mint for the verified result).
  The colour IS the state, not decoration.
- Film grain overlay so nothing reads as flat vector.
- Motion with weight and real easing (cubic-bezier(.16,1,.3,1) family). Nothing linear, nothing bouncy.
- Density: high-end sites are RICH with detail. Sparse outlined boxes read as wireframe, not design.

=== INTERACTION MODEL ===
Scroll IS the run button. The visitor triggers each pipeline themselves and watches the chaos resolve
under their own control — progressive reveal, each element building on the last. They are a participant,
not a spectator. No autoplaying loops.

=== SITE STRUCTURE (full portfolio, not a one-pager) ===
1. Home — cinematic hero, positioning, four flagship project worlds, capabilities, experience, archive, contact
2. Work — all four flagship systems plus the filterable archive
3. A dedicated case-study page per flagship project, each carrying its own full cinematic scene
4. Contact

=== THE FOUR FLAGSHIP PROJECTS ===
Each needs a DISTINCT visual world, colour identity, and motion grammar. No shared template.

--- 01. WeIN Agentic Offer Pipeline (n8n · LLMs · Python · RAG) ---
OPERATOR: The Offer Specialist.
BEFORE: A provider menu PDF open to page 3 of 11; a competitor research tab; an unread WhatsApp thread;
  a pricing spreadsheet named v7_FINAL_v2; a past-offers list being checked for duplicates by hand;
  a maps tab for manual location verification; draft copy on rewrite #4.
RUNNING: Those artifacts get swept into one orchestrated rail. Five real stages light in sequence:
  Intel → Concepts → Score → Create → Review. Three real validation gates resolve:
  merchant grounded, no duplicate, location verified.
AFTER: One review-ready offer card, explicitly awaiting human approval, with a visible marker at the
  human decision point.
COLOUR: amber → blue → mint.

--- 02. WeIN Operations Portal (Flask · Supabase · JavaScript · n8n) ---
OPERATOR: The Sales / Ops lead.
BEFORE: Deals tracked across scattered WhatsApp threads, a shared spreadsheet, and memory. No single
  source of truth; follow-ups falling through.
RUNNING: A living operating board assembles — Intake → Negotiation → Signed → Launched. Deal cards
  physically move between columns; portal chat and notifications fire; a launch checklist
  auto-generates on signature.
AFTER: The ops lead stops chasing status and starts working blockers — the board tells them where
  attention is needed.
COLOUR: teal / green identity, distinct from project 01.

--- 03. Medical SaaS / Clinic OS (Product · AI · Full-stack — IN DEVELOPMENT) ---
OPERATOR: The clinic front desk.
BEFORE: Drowning in phone calls, paper intake forms, sticky-note follow-ups, double-booked rooms.
RUNNING: An architectural blueprint assembles module by module — Intake, Scheduling, Patient Record,
  Cashier/Billing, Team, Reports — like an exploded diagram clicking into place.
AFTER: The front desk moves from transcription to triage.
MANDATORY: mark this visibly and explicitly as IN DEVELOPMENT. Never present it as launched.
  No customer counts, no uptime claims, no outcome numbers.
COLOUR: violet / indigo identity.

--- 04. Shore Thing (React 19 · Tailwind · Motion) ---
This one deliberately breaks the operator pattern — it is brand experience, not an ops system, so it
earns the most expressive treatment. A kinetic beach-sport and DJ-culture poster world: bouncing ball
physics, palm trees, scroll-driven day-to-night lighting following the real event rhythm
(arrival → beach games → golden hour → DJ set), resolving into a real "GET TICKETS" artifact.
COLOUR: warm sunset — amber, rose, cyan.

=== SUPPORTING ARCHIVE ===

  NO decorative preloaders, NO gatekeeping intros, NO navigation the visitor must decode.
- prefers-reduced-motion renders a complete, static, fully legible version of every scene.
- Mobile is conceptually equivalent, not stripped — reflow scenes to vertical/tap-driven, don't delete them.
- Lazy-load per section; nothing heavy blocks first paint.
- NO fabricated metrics. Any number is either real or absent. Leave clearly marked placeholders instead.
- Never imply an unfinished product is launched.
- Genuine light mode, art-directed — not a variable swap.
```
